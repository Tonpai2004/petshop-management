# One Pet Shop – ระบบจัดการร้านเพ็ทช็อป (Pet Shop Management System)

โปรเจกต์นี้ทำขึ้นเป็นแบบทดสอบตำแหน่ง Full Stack Developer ตามโจทย์ที่ได้รับ เป็นระบบหลังร้านของ **One Pet Shop** ร้านเพ็ทช็อปสมมติที่ขายอาหาร ขนม ของเล่น และอุปกรณ์สำหรับสัตว์เลี้ยง พนักงานล็อกอินเข้ามาเพื่อดูภาพรวมของร้าน จัดการรายการสินค้า และดูแลสต็อกไม่ให้ของขาดชั้นวาง

---

## ตีความโจทย์ยังไง

โจทย์บอกแค่ว่าเป็น "Pet Shop Management System" ไม่ได้ระบุว่าร้านขายอะไร ผมเลือกมองว่าเป็น **ร้านขายสินค้าสำหรับสัตว์เลี้ยง** และตั้งชื่อร้านสมมติว่า "One Pet Shop" ให้เข้ากับบริษัทที่สมัคร เพราะเป็นความหมายที่คนทั่วไปเข้าใจเมื่อพูดถึงร้านเพ็ทช็อป และทำให้ระบบหลังร้านมีงานจริงให้จัดการ คือ สต็อกสินค้า การสั่งของเพิ่ม และมูลค่าของในร้าน

สินค้าแต่ละชิ้นยังระบุด้วยว่าทำมาสำหรับสัตว์ชนิดไหน (สุนัข แมว นก ปลา สัตว์เลี้ยงขนาดเล็ก หรือใช้ได้ทุกชนิด) จึงยังกรองดูสินค้าตามสัตว์ได้

---

## วิธีรัน

ต้องติดตั้ง **.NET 8 SDK** และ **Node.js 20 ขึ้นไป** ไว้ก่อน

**1. เปิด API (หลังบ้าน)**

```bash
cd backend/src/PetShop.Api
dotnet run --launch-profile Development
```

API จะรันอยู่ที่ http://localhost:5080 และดูรายการ API ทั้งหมดได้ที่ http://localhost:5080/swagger

**2. เปิดหน้าเว็บ (หน้าบ้าน)** โดยเปิด terminal อีกหน้าต่างหนึ่ง

```bash
cd frontend
npm install
npm run dev
```

จากนั้นเข้าเว็บที่ http://localhost:3000

**บัญชีสำหรับทดลองใช้**

| สิทธิ์ | Username  | Password      | ทำอะไรได้บ้าง                                                       |
| ------------ | --------- | ------------- | -------------------------------------------------------------------------------- |
| Admin        | `admin` | `Admin@123` | ทำได้ทุกอย่าง รวมถึงลบสินค้าและจัดการทีม  |
| Staff        | `staff` | `Staff@123` | ดู เพิ่ม แก้ไข และปรับสต็อกได้ แต่ลบไม่ได้ |

**3. รันชุดทดสอบ** (ไม่บังคับ)

```bash
cd backend
dotnet test
```

## ใช้งานอะไรได้บ้าง

**หน้า Login**

- ล็อกอินด้วยชื่อผู้ใช้และรหัสผ่าน ถ้ากรอกไม่ครบหรือรหัสผิด ระบบจะแจ้งเตือน
- ใน Dev และ UAT มีปุ่มกดกรอกบัญชีทดลองให้อัตโนมัติ ส่วน Prod จะซ่อนปุ่มนี้
- ถ้ายังไม่ได้ล็อกอินแล้วพยายามเข้าหน้า Dashboard ระบบจะพากลับมาหน้า Login

**หน้า Dashboard**

- การ์ดสรุปจำนวนสินค้า มูลค่าสต็อก จำนวนสินค้าใกล้หมด และจำนวนสินค้าที่หมดแล้ว
- กราฟสินค้าแยกตามหมวด ว่าหมวดไหนมีของพอและหมวดไหนต้องสั่งเพิ่ม
- กล่อง "Stock health" แสดงสัดส่วนสต็อก และรายการ "Restock soon" ที่กดเติมสต็อกได้ทันที
- ตารางสินค้าที่ค้นหาจากชื่อ แบรนด์ หรือ SKU ได้ กรองตามหมวด สัตว์ และสถานะสต็อก เรียงลำดับ และแบ่งหน้าได้
- เพิ่ม แก้ไข และลบสินค้าผ่านหน้าต่างฟอร์ม ระบบตรวจข้อมูลก่อนบันทึก และแจ้งผลทุกครั้งที่ทำรายการ
- Responsive ใช้งานบนมือถือได้
- มีปุ่มสลับโหมดสว่าง/มืดที่แถบด้านบน (ค่าเริ่มต้นเป็นโหมดสว่าง และระบบจำค่าที่เลือกไว้)

## ฟีเจอร์ที่ต่อยอดเพิ่มจากโจทย์

ส่วนนี้ไม่ได้อยู่ในโจทย์ เป็นไอเดียที่ผมคิดร่วมกับ AI ว่าถ้าเป็นระบบหลังร้านที่ใช้งานจริง ควรมีอะไรเพิ่ม แล้วเลือกเฉพาะที่ทำเสร็จได้ทันเวลา ทุกฟีเจอร์ยังอยู่ในกรอบของโจทย์ คือ **ใช้ controller 2 ตัว (Auth กับ Products) และมี 2 หน้า (Login กับ Dashboard)** ส่วนที่เพิ่มมาใช้หน้าต่าง popup หรือแผงด้านข้างแทนการสร้างหน้าใหม่

**ปรับสต็อก (รับของเข้า / ขายออก)**

- บันทึกการเปลี่ยนแปลงสต็อกพร้อมเหตุผล ได้แก่ รับของเข้า ขาย ลูกค้าคืน ของเสีย/หมดอายุ และนับสต็อกใหม่
- ใส่หมายเหตุได้ เช่น เลขใบส่งของ และมีบรรทัดแสดงว่าสต็อกจะเปลี่ยนจากเท่าไหร่เป็นเท่าไหร่ก่อนกดบันทึก
- สต็อกติดลบไม่ได้ และถ้าสองคนปรับพร้อมกันตัวเลขก็ไม่เพี้ยน เพราะ API คำนวณในคำสั่งเดียว

**อัปโหลดรูปสินค้า**

- ลากรูปมาวาง หรือกดเลือกรูปในฟอร์มได้เลย มีภาพตัวอย่างให้ดูก่อนบันทึก
- ระบบย่อรูปในเบราว์เซอร์ก่อนส่ง รูปจากมือถือขนาดหลาย MB จึงอัปโหลดเร็วและไม่เปลืองพื้นที่
- ฝั่ง API ตรวจจากเนื้อไฟล์จริงว่าเป็นรูปภาพ (JPG/PNG/WebP) ไม่เชื่อแค่นามสกุลไฟล์ และตั้งชื่อไฟล์ใหม่แบบสุ่ม
- ถ้ายังไม่มีรูป ระบบแสดงไอคอนประจำหมวดสินค้าแทน
- ถ้าลบสินค้า ไฟล์รูปจะถูกลบไปด้วย

**แผงรายละเอียดสินค้า**

- กดที่แถวในตาราง หรือการ์ดในแถว "New on the shelf" จะมีแผงเลื่อนออกมาจากด้านขวา
- แสดงรูป จำนวนในสต็อก จุดสั่งซื้อ มูลค่าสต็อก SKU และข้อมูลอื่น พร้อมปุ่มปรับสต็อก แก้ไข และลบ
- มีส่วน "ประวัติ" ของสินค้าชิ้นนั้น ว่าใครเพิ่ม แก้ หรือปรับสต็อกไปเมื่อไหร่

**Export CSV**

- ปุ่ม Export CSV ดาวน์โหลดรายการตามตัวกรองที่เลือกอยู่ ครบทุกหน้า ไม่ใช่แค่หน้าที่เห็น
- มีคอลัมน์สถานะสต็อกและมูลค่าสต็อกให้ด้วย เปิดใน Excel แล้วภาษาไทยแสดงได้ถูกต้อง

**บันทึกกิจกรรม (Activity log)**

- เก็บทุกการกระทำสำคัญ เช่น เพิ่ม/แก้/ลบสินค้า ปรับสต็อก เปลี่ยนรูป ล็อกอิน เพิ่มพนักงาน และบัญชีถูกล็อก
- หน้า Dashboard มีกล่อง Recent activity ให้เห็นว่าทีมทำอะไรไปบ้าง และรีเฟรชเองทุก 1 นาที

**จัดการทีมงาน (เฉพาะ Admin)** เปิดจากเมนูชื่อผู้ใช้ที่มุมขวาบน

- เพิ่มพนักงานใหม่ โดยกำหนดชื่อ ชื่อผู้ใช้ รหัสผ่านชั่วคราว และสิทธิ์
- ปิดหรือเปิดบัญชีได้ บัญชีที่ถูกปิดจะใช้งานต่อไม่ได้ทันที แม้จะล็อกอินค้างไว้อยู่ก็ตาม
- รีเซ็ตรหัสผ่านให้พนักงาน ซึ่งปลดล็อกบัญชีไปในตัว
- Admin ปิดบัญชีของตัวเองไม่ได้ ป้องกันกรณีไม่เหลือใครเข้าระบบได้

**เปลี่ยนรหัสผ่านของตัวเอง**

- ทุกคนเปลี่ยนรหัสของตัวเองได้จากเมนูผู้ใช้ ต้องกรอกรหัสเดิมก่อน
- รหัสผ่านใหม่ต้องยาว 8 ตัวขึ้นไป และมีตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก และตัวเลข

**กันการเดารหัสผ่าน**

- กรอกรหัสผิด 5 ครั้งติดกัน บัญชีจะถูกล็อก 5 นาที และระบบบันทึกลง Activity log
- จำกัดจำนวนครั้งที่เครื่องหนึ่งเรียกหน้าล็อกอินได้ต่อนาที กันการสุ่มเดาหลายบัญชีพร้อมกัน
- ตั้งค่าตัวเลขเหล่านี้ได้ใน `appsettings.json` ส่วน `Security`

> บัญชีทดลองที่ระบบสร้างให้ (`admin` / `staff`) ใช้รหัสเดิม ถ้าอยากทดสอบการล็อก แนะนำให้สร้างพนักงานใหม่ขึ้นมาทดสอบ จะได้ไม่ล็อกบัญชีหลัก

## หน้าตาและธีม

ผมอยากให้ระบบนี้ดูเข้ากับบริษัทที่สมัคร เลยเอาเว็บ one31.net กับ oned.net มาเป็นแรงบันดาลใจ แล้วปรับให้เข้ากับร้านเพ็ทช็อป

**สิ่งที่หยิบมาจากเว็บช่องวัน**

- **สีหลัก:** ชมพูแมเจนต้าแบบเดียวกับปุ่มและเมนูของ oneD ใช้กับปุ่ม กราฟ และตัวเลขราคา
- **ฟอนต์:** Prompt ตัวเดียวกับ oneD อ่านง่ายทั้งไทยและอังกฤษ
- **แถบด้านบน:** สีดำทั้งในโหมดสว่างและมืด เหมือนแถบเมนูของ one31
  - มีเมนู Overview / Insights / Products ที่มีเส้นใต้สีชมพูวิ่งตามส่วนที่กำลังดูอยู่
  - ปุ่มค้นหากดคีย์ลัด `/` ได้ (แบบ GitHub)
  - โปรไฟล์ผู้ใช้อยู่มุมขวา
- **หัวข้อแต่ละส่วน:** มีขีดสีชมพูนำหน้า คล้ายหัวข้อแถวละครในเว็บ
- **แถว "New on the shelf":** โชว์สินค้าที่เพิ่งเข้าร้านเป็นการ์ดเรียงกัน คล้ายแถวโปสเตอร์ละคร บนมือถือปัดซ้าย-ขวาได้

**ส่วนที่คงความเป็นร้านเพ็ทช็อปไว้**

- โลโก้รูปอุ้งเท้า และไอคอนประจำหมวดสินค้าแต่ละสี (อาหาร ขนม ของเล่น อุปกรณ์ ฯลฯ)
- ไอคอนสัตว์บอกว่าสินค้าทำมาสำหรับสัตว์ชนิดไหน
- สีป้ายสต็อกที่ดูแล้วเข้าใจทันที คือ เขียว = มีของ, เหลือง = ใกล้หมด, แดง = หมด, เทา = เลิกขาย
- ตั้งค่าเริ่มต้นเป็นโหมดสว่าง เพราะเป็นระบบที่พนักงานใช้ทั้งวัน โหมดมืดล้วนแบบเว็บดูละครจะดูหนักเกินไปสำหรับงานหลังร้าน

## ออกแบบข้อมูลไว้แบบนี้

ข้อมูลทั้งหมดอยู่ในโฟลเดอร์ `backend/src/PetShop.Api/Database` โดย 1 ไฟล์ = 1 ตาราง

- **users.json** เก็บข้อมูลผู้ใช้ ได้แก่
  - ชื่อ และสิทธิ์ (Admin/Staff)
  - รหัสผ่านที่เข้ารหัสแล้ว ระบบไม่เก็บรหัสผ่านจริง
  - สถานะเปิด/ปิดบัญชี และจำนวนครั้งที่กรอกรหัสผิด สำหรับระบบล็อกบัญชี
- **categories.json** เก็บหมวดสินค้า ได้แก่ อาหาร ขนม ของเล่น อุปกรณ์ อาบน้ำ/ทำความสะอาด สุขภาพ และที่อยู่อาศัย (กรง ตู้ปลา ที่นอน)
- **products.json** เก็บสินค้าแต่ละรายการ ได้แก่
  - SKU (รหัสบนป้ายราคา ห้ามซ้ำ) ชื่อ แบรนด์ หมวด และสัตว์ที่ใช้
  - ขนาดบรรจุ ราคา จำนวนในสต็อก และจุดสั่งซื้อ (ต่ำกว่าเท่านี้ถือว่าใกล้หมด)
  - สถานะ (ขายอยู่/เลิกขาย) และหมายเหตุ
  - บันทึกว่าใครเพิ่มหรือแก้ไขล่าสุด
- **activities.json** เก็บบันทึกกิจกรรม ได้แก่ ใคร ทำอะไร กับข้อมูลไหน และเมื่อไหร่

สถานะสต็อก (มีของ / ใกล้หมด / หมด) ไม่ได้เก็บลงไฟล์ ระบบคำนวณจากจำนวนในสต็อกเทียบกับจุดสั่งซื้อทุกครั้ง ข้อมูลจึงไม่มีทางขัดกันเอง

รูปที่อัปโหลดเก็บแยกไว้ในโฟลเดอร์ `backend/src/PetShop.Api/Uploads` ไฟล์ JSON เก็บแค่ที่อยู่ของรูป

เมื่อรันครั้งแรก ระบบมีข้อมูลตัวอย่างให้ลองใช้ได้ทันที (สินค้า 24 รายการ จาก 7 หมวด) ถ้าอยากล้างข้อมูลกลับเป็นค่าเริ่มต้น ให้ปิด API ลบไฟล์ในโฟลเดอร์ `Database` แล้วรันใหม่

> ข้อมูลตัวอย่างทั้งหมดใช้ AI ช่วยสร้าง เพื่อให้เห็นภาพการใช้งานจริงตั้งแต่เปิดระบบครั้งแรก ไม่ใช่ข้อมูลจริงของร้านใด ได้แก่
>
> - รายการสินค้า ชื่อ แบรนด์ SKU ขนาดบรรจุ ราคา จำนวนสต็อก จุดสั่งซื้อ และหมายเหตุ
> - ชื่อผู้ใช้ตัวอย่าง
>
> ระบบตั้งตัวเลขบางส่วนไว้ให้ใกล้หมดหรือหมด เพื่อให้เห็นการแจ้งเตือนสต็อกและรายการ Restock soon ทำงาน ชื่อแบรนด์ใช้แค่ประกอบให้สมจริง ราคาไม่ได้อ้างอิงราคาจริงในตลาด
>
> รูปสินค้าตัวอย่างเป็นรูปฟรีจาก [Unsplash](https://unsplash.com/license) ที่เลือกให้เข้ากับสินค้าแต่ละชิ้น ระบบเก็บไว้เป็นลิงก์ จึงต้องต่ออินเทอร์เน็ตถึงจะแสดงรูป เปลี่ยนเป็นรูปของร้านเองได้ด้วยการอัปโหลดในหน้าแก้ไขสินค้า

## ทำยังไง และทำไมถึงเลือกแบบนี้

**ใช้ Dapper กับไฟล์ JSON**
ข้อนี้ต้องคิดหาวิธีพอสมควร เพราะ Dapper ทำงานกับฐานข้อมูลที่รับคำสั่ง SQL เท่านั้น อ่านไฟล์ JSON ตรง ๆ ไม่ได้ ผมเลยทำแบบนี้:

- ตอนเปิดระบบ โหลดข้อมูลจากไฟล์ JSON เข้าไปในฐานข้อมูลชั่วคราวที่อยู่ในหน่วยความจำ (SQLite)
- ให้ Dapper ทำงานกับฐานข้อมูลนั้นด้วย SQL ตามปกติ
- ทุกครั้งที่มีการเพิ่ม แก้ไข หรือลบ ระบบจะเขียนข้อมูลกลับลงไฟล์ JSON ทันที

ไฟล์ JSON จึงยังเป็นที่เก็บข้อมูลจริงตามที่โจทย์ต้องการ และถ้าวันหนึ่งเปลี่ยนไปใช้ฐานข้อมูลจริงอย่าง SQL Server ก็แก้เพิ่มไม่มาก

**แบ่งโค้ดเป็นชั้น ๆ**

- **หลังบ้าน:** แยกหน้าที่ชัดเจน คือ ส่วนรับคำขอ (Controller) ส่วนกฎทางธุรกิจ (Service) และส่วนคุยกับข้อมูล (Repository)
- **หน้าบ้าน:** แยกโฟลเดอร์ตามฟีเจอร์ คือ `auth`, `products`, `team` และ `activity` เพื่อให้หาโค้ดง่ายและต่อยอดได้

**เรื่องความปลอดภัยพื้นฐาน**

- ล็อกอินด้วย JWT และเข้ารหัสรหัสผ่านด้วย BCrypt
- API ที่จัดการข้อมูลต้องล็อกอินก่อนทุกครั้ง
- เฉพาะ Admin เท่านั้นที่ลบสินค้าและจัดการทีมได้
- ล็อกบัญชีเมื่อกรอกรหัสผิดหลายครั้ง และจำกัดจำนวนการล็อกอินต่อนาที
- ไฟล์ที่อัปโหลดถูกตรวจจากเนื้อไฟล์จริง และไม่ใช้ชื่อไฟล์เดิมจากผู้ใช้

**รายการ API**

| ---------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------- |

| Auth       | `PATCH /api/auth/users/{id}/status`                        | เปิด/ปิดบัญชี (Admin)                                                 |
| Auth       | `POST /api/auth/users/{id}/reset-password`                 | รีเซ็ตรหัสผ่าน (Admin)                                              |
| Products   | `GET /api/products`                                        | รายการ พร้อมค้นหา กรอง เรียง และแบ่งหน้า      |

| Products   | `POST /api/products/{id}/stock`                            | ปรับสต็อก (รับเข้า / ขาย / คืน / เสีย / นับใหม่) |
| Products   | `POST` / `DELETE /api/products/{id}/image`               | อัปโหลด / ลบรูป                                                       |
| Products   | `GET /api/products/export`                                 | ดาวน์โหลด CSV                                                            |
| Products   | `GET /api/products/summary`                                | ตัวเลขสรุปบน Dashboard                                                |
| Products   | `GET /api/products/categories`                             | รายชื่อหมวดสินค้า                                                |
| Products   | `GET /api/products/activity`                               | บันทึกกิจกรรมทั้งหมด                                          |
| Products   | `GET /api/products/{id}/activity`                          | บันทึกกิจกรรมของสินค้าแต่ละชิ้น                    |

ดูรายละเอียดและทดลองยิงได้ที่ Swagger

**ชุดทดสอบ:** มีเทสอัตโนมัติ 41 ตัว รันด้วย `dotnet test` ครอบคลุม

- การล็อกอิน และสิทธิ์การใช้งาน
- การตรวจข้อมูล (รวมถึง SKU ซ้ำ)
- CRUD และการปรับสต็อก (รวมถึงกรณีสต็อกติดลบ)
- การอัปโหลดรูป และการ export
- การล็อกบัญชี และการจัดการทีม

**แยก Environment**

- หน้าบ้านมีไฟล์ `.env` แยกเป็น Dev, UAT และ Prod ตามโจทย์
  - แต่ละไฟล์กำหนดที่อยู่ API, ชื่อแอป, timeout และการแสดงบัญชีทดลอง (Prod ปิดไว้)
  - หลังบ้านก็แยกการตั้งค่าตาม environment เหมือนกัน
- คำสั่งรันแต่ละ environment:

| Environment | รันแบบ dev     | Build                  |
| ----------- | -------------------- | ---------------------- |
| Dev         | `npm run dev`      | `npm run build:dev`  |
| UAT         | `npm run dev:uat`  | `npm run build:uat`  |
| Prod        | `npm run dev:prod` | `npm run build:prod` |

> ที่อยู่ API ของ UAT และ Prod ในไฟล์ `.env` เป็นที่อยู่ตัวอย่าง ถ้าจะ deploy จริงต้องเปลี่ยนเป็นที่อยู่ของเซิร์ฟเวอร์จริง

## เรื่องการใช้ AI ช่วยทำงาน

ในโปรเจกต์นี้ผมใช้ AI (Claude) เป็นเครื่องมือช่วยทำงานในบางส่วน เพื่อให้ทำงานได้เร็วขึ้น และเปิดมุมมองให้เห็นหลายแนวทางก่อนลงมือ เหมือนที่ใช้ Git, Swagger หรือเครื่องมืออื่น ๆ ในการทำงานประจำวัน ส่วนที่ใช้ AI ช่วยมีดังนี้

- **งานที่ต้องเขียนซ้ำ ๆ:** ร่างโค้ดโครง เช่น DTO, ฟอร์ม และชุดเทส ทำให้มีเวลาไปโฟกัสกับ logic ของระบบมากขึ้น
- **ตรวจโค้ด:** ช่วยรีวิวและหาจุดที่อาจผิดพลาดหรือตกหล่น
- **ข้อมูลตัวอย่าง:** สร้างรายการสินค้าพร้อมรายละเอียด หมวดสินค้า ชื่อผู้ใช้ และประวัติกิจกรรมเริ่มต้น เพื่อให้ระบบดูสมจริงและเห็นภาพการใช้งานตั้งแต่เปิดครั้งแรก
- **หน้าตาและธีม:** เสนอแนวทางนำธีมของช่องวันมาใช้กับร้านเพ็ทช็อป ตั้งแต่ดูสีและฟอนต์จากเว็บจริง ทำโหมดสว่าง/มืด ไปจนถึงไอเดียแถวสินค้าใหม่แบบแถวโปสเตอร์
- **ต่อยอดฟีเจอร์:** ระดมไอเดียว่าระบบหลังร้านจริงควรมีอะไรเพิ่ม จนได้ฟีเจอร์ในหัวข้อ "ฟีเจอร์ที่ต่อยอดเพิ่มจากโจทย์"
- **เอกสาร:** ช่วยเรียบเรียง README ให้อ่านง่าย

สำหรับผม AI เป็นเครื่องมือช่วยเพิ่มความเร็ว ไม่ได้มาแทนความเข้าใจ ทุกส่วนที่ AI ช่วยร่าง ผมนำมาอ่าน ปรับให้เข้ากับโปรเจกต์ และทดสอบจนใช้งานได้จริง

## ถ้ามีเวลาเพิ่ม อยากทำต่อ

- หน้าขายหน้าร้าน (POS) ที่ตัดสต็อกให้อัตโนมัติ และตารางการขายสำหรับดูยอดขายรายวัน
- ข้อมูลผู้จำหน่าย (supplier) และใบสั่งซื้อ เมื่อสินค้าถึงจุดสั่งซื้อ
- วันหมดอายุของอาหารและยา พร้อมแจ้งเตือนก่อนหมดอายุ
- เก็บ session ด้วย cookie แบบ httpOnly และมี refresh token
- เก็บรูปบน cloud storage (เช่น S3) แทนดิสก์ของเซิร์ฟเวอร์ ซึ่งโค้ดเตรียมไว้ให้เปลี่ยนได้ง่ายแล้ว
- ทำ Docker และระบบรันเทสอัตโนมัติ (CI)
